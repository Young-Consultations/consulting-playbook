# AI-SDLC Case Studies

This directory holds curated, evidence-backed, usually resolved examples for consulting conversations, presentations, training, and content. Create a case study selectively; a defect or journal entry does not automatically warrant one.

A case study should normally be created only after:

- the defect or discovery is understood;
- relevant requirements or architecture decisions are resolved by their authority;
- the implementation outcome is known; and
- sufficient, appropriately handled evidence is available.

Copy [the template](TEMPLATE.md), remove sensitive or identifying detail, disclose material evidence limitations, and link source records. A case study interprets an outcome; it does not become authoritative product documentation.

The existing [`consulting/10-case-studies/`](../../consulting/10-case-studies/README.md) area contains client-engagement case-study guidance and an existing internal outline. It remains the consulting operating system's engagement artifact area. This directory has the narrower role of curated organization-wide **AI-SDLC learning evidence**, avoiding migration or duplication of those existing assets.
