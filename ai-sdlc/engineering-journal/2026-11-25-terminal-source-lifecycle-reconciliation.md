## Lesson and remaining boundaries

A green transport/projection job does not imply a correct source lifecycle. Durable terminal evidence should outrank stale display state. Test failure after successful writes as well as failure before writes: idempotency means convergence without duplicate visible effects. Keep failed execution distinct from accepted work, historical recovery distinct from new authority, and missing evidence distinct from conflicting evidence.

Normal source projection was verified with offline fake API and effect traps, not a new production dispatch. GitHub label APIs are not atomic with manual changes; concurrency can cancel a pending job. Conservative trust policy only supports v3.0.3/v4 and one admission per issue; unsupported cases require human reconciliation. The v5 source migration must revisit the trust binding.
