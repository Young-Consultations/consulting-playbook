# Client Qualification Checklist

## Active pilot qualification

Use the [canonical pilot](../01-service-offer/active-software-delivery-assessment-pilot.md).
Generic interest in delivery or AI is insufficient. Record a yes/no and sanitized
basis for each gate in the authorized engagement workspace, outside this repository.

| Gate | Yes/No | Evidence / condition |
| --- | --- | --- |
| Exactly one concrete delayed feature, integration handoff, or release decision named and bounded | | |
| Buyer wants a specific action or decision within 30 days; date and impact identified | | |
| Buyer has purchasing authority, budget, and authority to sponsor action; decision owner named | | |
| No more than five suitable sanitized artifacts available, with permissions and sufficient relevance to the decision | | |
| Kickoff/readout availability and agreed input date support five-business-day turnaround | | |
| Review, report, meetings, and one revision fit the five-hour delivery-effort cap | | |
| Buyer understands fee/payment hypotheses, output limits, exclusions, and advisory responsibility | | |
| Confidentiality, conflicts, and evidence handling permit safe engagement | | |

Proceed only when all gates pass. For conditions, identify owner and closure date
before booking; otherwise reduce scope, refer, decline, or separately qualify a
larger engagement. Do not accept more evidence or promise extra analysis to force fit.
