# Authoritative Glossary

| Term | Definition |
| --- | --- |
| Acceptance criterion | Observable condition used to determine whether a requirement or outcome is satisfied. |
| AI assistance | Machine-generated analysis, drafting, classification, or execution support that remains subject to evidence validation and human review. |
| Approved recommendation | A recommendation a named authority has accepted within stated scope and conditions; it is not by itself task execution authority. |
| Assessment | Contextual evaluation of a defined subject against stated questions, evidence, and criteria. |
| Assessment domain | A coherent subject area such as architecture, backlog, quality, or AI readiness. |
| Assumption | A proposition treated as true for a bounded purpose but not confirmed; it includes a validation or change condition where material. |
| Authority | A person or body explicitly empowered to make a defined decision; participation, authorship, and expertise do not imply authority. |
| Baseline | Dated, scoped representation of current state and measures used for comparison. |
| Capability | Demonstrated ability to achieve a relevant outcome in context; it is not synonymous with process adoption. |
| Classification | Handling category that determines permitted access, use, transfer, retention, and disposal. |
| Client evidence | Engagement information owned or controlled by a client or designated custodian; it is not repository-owned merely because referenced. |
| Confidence | Qualitative, evidence-based expression of how strongly the available information supports a conclusion, including uncertainty. |
| Consulting playbook | The reusable consulting operating system owned by this repository; not a counseling service and not the portfolio backlog. |
| Consulting recommendation | Evidence-linked proposal for action or decision. It does not authorize execution. |
| Consulting operating system | The governed set of principles, lifecycle guidance, methods, knowledge assets, and trace semantics used to conduct and improve consulting work. |
| Control plane | Organization-owned capability for shared AI-SDLC contracts, routing, registration, compatibility, and verification. |
| Correlation identity | Stable value relating records/events across a logical work journey; it is distinct from delivery identity unless a contract says otherwise. |
| Current state | Scoped account of relevant outcomes, systems, processes, roles, dependencies, constraints, and decisions at a stated time. |
| Decision | Attributable selection, rejection, deferral, condition, or supersession made by a designated authority. |
| Delivery identity | Stable idempotency identity for one logical target publication; workflow run identity is not a substitute. |
| Engagement | Bounded consulting undertaking with sponsor, objectives, scope, participants, decisions, constraints, and measures. |
| Engagement type | Reusable pattern for an engagement purpose that selects or recommends applicable methods and outputs. |
| Evidence | Information used to support or contradict a claim, with source, provenance, scope, limitations, and handling conditions. |
| Evidence register | Index of evidence metadata and safe locators; it need not contain the evidence itself. |
| Finding | Evidence-evaluated statement about the assessed context, distinct from raw observation, implication, recommendation, and decision. |
| Follow-up | Later evidence-based comparison against the original baseline, decisions, intended outcomes, and context. |
| Handoff package | Evidence-minimized, target-specific proposal suitable for separate portfolio intake and governance. |
| Implication | Consequence or significance of a finding for an outcome, stakeholder, risk, or decision. |
| Knowledge asset | Governed reusable principle, method, checklist, template, pattern, framework, or generalized lesson. |
| Limitation | Condition restricting evidence, analysis, applicability, confidence, or interpretation. |
| Managed draft | Draft pull request whose ownership metadata exactly matches one authorized logical delivery. |
| Material | Important enough that omission or misstatement could reasonably change a decision, priority, risk response, or conclusion. |
| Maturity | Contextual developmental characterization based on observable capability anchors; never an automatic universal target. |
| Method | Reusable, tailorable guidance for reaching a consulting outcome; it is not necessarily an automated procedure. |
| Observation | Directly perceived or measured information before evaluative synthesis into a finding. |
| Option | Credible response path evaluated for outcomes and trade-offs, including no action/status quo where appropriate. |
| Portfolio task | Authoritative, externally governed unit of proposed or approved work owned by the portfolio system, not this repository. |
| Professional review | Accountable human evaluation of evidence, reasoning, applicability, safety, and communication. |
| Recommendation pattern | Reusable structure or precedent that assists advice but never predetermines an engagement conclusion. |
| Roadmap | Sequenced outcomes, owners, dependencies, decision points, risks, and learning checkpoints; not execution authority. |
| Root cause | Systemic causal condition supported sufficiently for the stated context, distinct from a symptom or untested hypothesis. |
| Sensitive information | Information requiring restricted handling due to client, privacy, security, legal, contractual, or organizational obligation. |
| Symptom | Observable effect or outcome that may arise from one or more underlying conditions. |
| Tailoring | Explicit selection, omission, depth change, or adaptation of a reusable method for engagement context, with rationale. |
| Target repository | Repository explicitly authorized to receive a target-specific execution request. |
| Traceability | Ability to navigate and audit relationships among context, evidence, conclusions, decisions, action, and outcomes. |
| Validation | Confirmation that information or an artifact is suitable for its intended purpose under stated criteria; not necessarily proof of objective truth. |
| Verification | Confirmation that specified requirements or rules have been met. |
| Vision goal (VG) | Traceability label for an intended outcome derived from `docs/VISION.md`; labels do not amend the vision. |
| Working assumption | Unconfirmed proposition temporarily used for requirements planning and explicitly subject to validation. |

## Prohibited conflations

Finding ≠ implication ≠ recommendation ≠ decision ≠ task. Evidence reference ≠
evidence ownership. Priority ≠ approval. Roadmap ≠ authorization. AI output ≠
professional judgment. Template completion ≠ compliance. Activity ≠ outcome.
